## 1. What This Platform Does — The Core Loop

This is the single most important thing to understand before touching any code.

```
NIGHT (automated)
  Drones patrol industrial site
  Sensors capture: motion, badge swipes, vehicle movement, environmental readings
  Events arrive at POST /api/v1/events via drone API key

OVERNIGHT (automated)
  BullMQ worker processes events
  Claude agent investigates, correlates, classifies each incident
  Investigation results written to MongoDB
  Morning briefing generated by Claude

MORNING (operator-triggered)
  Operator logs in → /investigate shows last night's work
  Operator reviews incidents, approves/escalates
  Operator approves morning briefing → distributed via webhook
```

**Every UI decision, every route, every feature must serve this loop.**
If a feature does not help an operator understand last night faster, question it.

## 6. Authentication Architecture

### Current Flows

| Flow | Steps |
|---|---|
| Register | email+password → bcrypt hash → OTP emailed (sha256 stored) → JWT issued |
| Login | bcrypt.compare → JWT (15m) + refresh (7d) as httpOnly cookies |
| Refresh | refreshToken verified → tokenVersion checked → new accessToken issued |
| Password reset | OTP emailed (sha256 stored, 20m expiry) → submit OTP → new password |
| Force logout | increment `tokenVersion` on user → all existing tokens invalidated |

### Token Storage Rules

- **Access token**: httpOnly cookie `accessToken` — never localStorage
- **Refresh token**: httpOnly cookie `refreshToken` — never localStorage
- **API key (raw)**: shown once at creation — never stored in DB, only SHA-256 hash
- **OTP (raw)**: emailed — never stored in DB, only SHA-256 hash

### Middleware Chain (server)

```
verifyJWT           — validates JWT, checks user.isActive, checks tokenVersion
  └─ requireRole    — ['super_admin'] | ['org_admin', 'super_admin'] | etc.
       └─ scopeToOrg — attaches req.orgFilter = { orgId: user.orgId }
                        checks org suspended (Redis cache, 5min TTL)
```

Always use `req.orgFilter` in queries — never trust client-supplied orgId.

## 7. Security Model — What Is and Isn't Encrypted

### In Transit ✅
All external traffic must use HTTPS/TLS. Configure in Nginx (production).
In development, HTTP is acceptable for localhost only.

### Passwords ✅
`bcrypt` hash, rounds=10. Raw password never stored.

### API Keys ✅
SHA-256 hash stored. Raw key shown once at creation, never persisted.

### OTPs ✅
SHA-256 hash stored, 20-minute TTL. Raw OTP sent by email only.

### JWTs ✅
Short-lived (15m), httpOnly cookies, tokenVersion for instant invalidation.

### MongoDB at rest ⚠️
- Atlas: enable Encrypted Storage Engine in cluster settings
- Self-hosted: enable WiredTiger encryption
- Currently unconfirmed in this codebase

### Redis payloads ⚠️
Job payloads stored plaintext. Use Redis ACLs + TLS (`rediss://`) in production.
Avoid storing PII in BullMQ job data — use document IDs only.

### Webhook payloads ⚠️
HMAC-SHA256 signing not confirmed. Add `X-Ridgeway-Signature` header to all outgoing webhooks.

## 9. ⚠️ MISSING: Two-Factor Authentication (2FA)

**Status:** Email template says "Enable two-factor authentication if available" but it is NOT implemented.

### Design

2FA should be **optional, org-admin-enabled, TOTP-based** (Google Authenticator / Authy compatible).

### Backend Changes Required

Add to `user.models.js`:
```js
twoFactorEnabled: { type: Boolean, default: false },
twoFactorSecret: { type: String },       // encrypted with AES-256 before storage
twoFactorBackupCodes: [{ type: String }] // hashed with SHA-256
```

New routes (add to `auth.routes.js`):
```
POST /auth/2fa/setup    — generate TOTP secret, return QR code URI
POST /auth/2fa/verify   — verify TOTP code, enable 2FA, return backup codes
POST /auth/2fa/disable  — disable 2FA (requires password confirmation)
POST /auth/login/2fa    — second step after password login when 2FA is on
```

### Login Flow with 2FA

```
POST /auth/login (email+password)
  → if user.twoFactorEnabled:
      return { requires2FA: true, tempToken: <short-lived JWT, 5min> }
  → client shows TOTP input screen
  → POST /auth/login/2fa { tempToken, code }
      verify TOTP code using speakeasy/otplib
      issue full access + refresh tokens
  → else: issue tokens immediately (current behaviour)
```

### Recommended Library

```bash

bun add otplib qrcode
```

## 13. API Reference Summary

## 16. Code Style Rules

- **No `console.log` in production code** — use `pino` logger: `logger.info({...}, 'message')`
- **All DB queries must include `req.orgFilter`** — never query without org scope
- **Always use `asyncHandler()`** — wrap all async Express controllers
- **Throw `ApiError`, not plain `Error`** — `throw new ApiError(404, 'Not found')`
- **Return `ApiResponse`** — `res.status(200).json(new ApiResponse(200, data, 'message'))`
- **No inline styles in Tailwind pages** — use CSS tokens for Night Watch components
- **Keep agent tools idempotent** — tool calls may be retried by the ReAct loop
- **Never store raw secrets** — passwords: bcrypt, OTPs: sha256, API keys: sha256

## 17. Incident Lifecycle

```
open
  └─ investigating   (Claude agent running)
       └─ reviewed    (operator has reviewed)
            └─ escalated  (sent to external team)
            └─ closed     (resolved, no action)
```

Severity levels (set by Claude agent during classification):

| Level | Meaning | Operator action |
|---|---|---|
| `serious` | Immediate threat — intruder, fire, breach | Escalate |
| `minor` | Needs monitoring — repeated badge fails, unusual vehicle | Review |
| `harmless` | Routine — wildlife, known vehicle, false positive | Close |
| `uncertain` | Insufficient evidence for classification | Request follow-up |
